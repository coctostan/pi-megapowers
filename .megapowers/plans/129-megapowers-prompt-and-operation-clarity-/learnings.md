# Learnings — #129 Megapowers prompt and operation clarity

- **A single allowed-action mapping is the only way to keep compact prompt and `deriveToolInstructions` from drifting.** Once a `signalActionFor()` guard was added inside `tool-instructions.ts` that throws if it mentions a `megapowers_signal` action not in the mapping, the rest of the parity work (header text vs phase guidance) became a near-trivial table edit rather than a coordination chore across files.
- **`composeMessage` works precisely because the shape is small.** Five icons, four optional fields (`summary`, `changes`, `artifactPath`, `nextStep`). Anything richer would have leaked into the tools and re-spread the divergence problem. Future feedback-shape changes should add new optional fields only, not reorder the existing four.
- **"Fields set" is not the same as "fields changed".** The original update path reported every field whose value was *supplied*, even when the new value equaled the old one — the "no changes when only the description was rewritten unchanged" case in AC45 only failed under a hand-crafted test. Always diff against `existing.data` for change-list reporting, not against `undefined`.
- **Error-paths can silently mutate state.** The original `handlePlanReview` wrote the review artifact and task-status updates before delegating to `handleReviseVerdict`, so a rejected revise verdict at the iteration cap still left disk side effects. Always run mode/policy checks *before* persisting anything, even if the previous implementation worked by accident.
- **Untracked files entered the working tree during code review.** Local dev artifacts (`.codegraph/`, `.pi/npm/`, the prompt-assembler registry overwrites) appeared during the implementation phase even though they were not part of the change. Worth excluding them via `.gitignore` updates in a follow-up; for this issue I reverted the one file (`.pi/prompt-assembler/registry.json`) that had been modified, but left untracked files alone.
- **`impact` with `signature_change` is the right read for "did this break callers?"** Once the compact-header refactor landed, running `impact` on the modified public symbols (`buildInjectedPrompt`, `getAllowedActions`, `composeMessage`, the four `handle*` exports) produced a clean dependents list confirming no existing call site relied on the old return strings beyond substring-overlap assertions already in the test suite.
- **Prompt content tests are most readable when written against the smallest unique substring.** Asserting `toContain("plan (draft)")` and `toContain("plan_draft_done")` is much more robust to wording tweaks than asserting full-line equality, but still fails fast on real regressions.
